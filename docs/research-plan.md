# 금융 사기 탐지 모델의 적대적 강건성 평가 및 방어 기법 적용

**연구 질문**
사기꾼이 현실적으로 조작 가능한 항목만 변경하여 사기 탐지 모델을 회피할 수 있는가?
가능하다면 표준적 방어로 얼마나 복구되며, 그 대가는 무엇인가?

김태우 · 순천향대학교 AI·빅데이터학과 · 지도교수 김재윤
2026년 8월

---

## 1. 연구 배경

### 1.1 검증되지 않은 가정

사기 탐지 모델은 통상 테스트셋 정확도로 평가한 뒤 배포된다. 이 평가에는 명시되지 않은 가정이 하나 있다.

> **사기꾼이 모델의 존재와 무관하게 행동한다**

현실은 그렇지 않다. 사기꾼은 탐지를 회피하기 위해 거래 방식을 능동적으로 조정한다. 탐지 모델이 없다면 200만원을 한 번에 결제하겠지만, 모델이 있기 때문에 15만원씩 나누어 결제한다. **모델의 존재 자체가 입력 데이터의 성격을 바꾼다.**

따라서 무작위 추출한 테스트셋에서 측정한 성능은 평균적 성능일 뿐이며, 적대적 상황에서의 최악 성능을 보장하지 않는다.

### 1.2 일반적 평가와 적대적 평가

| | 일반 테스트 | 적대적 평가 |
|---|---|---|
| 데이터 출처 | 원 분포에서 무작위 추출 | 모델이 오분류하는 방향으로 의도적 탐색 |
| 측정 대상 | 평균 성능 | 최악 성능 |
| 실패 사례 | 우연히 발견 | 발견될 때까지 반복 시도 |
| 입력의 현실성 | 실제 분포를 따름 | 도메인 제약을 강제해야 확보됨 |

이 구분이 본 연구의 논리적 출발점이다.

### 1.3 이미지 도메인과의 차이

적대적 공격 연구는 대부분 이미지 인식에서 발전했다. 이미지는 모든 픽셀을 자유롭게 변경할 수 있으나 금융 거래는 그렇지 않다. 이 차이가 기존 기법을 그대로 적용할 수 없게 만든다.

| 구분 | 항목 | 근거 |
|---|---|---|
| 조작 가능 | 거래 금액, 거래 시각 | 공격자가 직접 결정 |
| 조작 불가 | 카드 식별 정보, 주소, 과거 이력 기반 집계값 | 탈취한 카드의 속성이거나 과거에 확정됨 |
| 추가 제약 | 변형 후에도 사기로서 유효해야 함 | 금액을 0으로 만들면 공격 목적 상실 |

**이 제약을 강제하는 것이 본 연구의 핵심이자 구현상 가장 많은 작업을 요구하는 부분이다.**

## 2. 선행 연구

### 2.1 주요 연구

| 연구 | 내용 | 한계 |
|---|---|---|
| Carminati et al. (2020), RAID | 실제 은행 데이터로 회피 공격 수행. 공격자 지식 수준별로 60~100% 회피율 보고 | 데이터 비공개 — 재현 불가 |
| Cartella et al. (2021), Sony | 정형 데이터의 도메인 제약(수정 가능 항목, 값 범위)을 정식화. 임계값 보정으로 공격 성공률 0%→100% | IEEE-CIS 실험 결과를 지면 사유로 미수록 |
| Lunghi et al. (2023), DEC | 사기 탐지 적대적 학습 개관. 도메인 특수성 정리 | 개관 논문 — 실험 없음. **향후 과제로 "공개 데이터셋에서의 기존 공격 비교"를 명시** |
| Lunghi et al. (2026), IEEE TDSC | Fraud-RLA. 강화학습 기반 무지식 공격 | 시뮬레이션 데이터만 사용. **방어를 향후 과제로 남김** |

### 2.2 문헌의 공백

1. **재현 가능한 공개 결과의 부재** — 비공개 데이터를 사용했거나, 공개 데이터 결과가 논문에 수록되지 않았다.
2. **방어의 부재** — 대부분 "공격이 통한다"에서 종료된다. 2026년 최신 연구도 방어를 미완으로 남겼다.
3. **평가 절차의 불투명** — 데이터 분할 방식과 판정 임계값 설정이 명시되지 않은 경우가 많다.

### 2.3 본 연구의 기여

1. 공개 데이터(IEEE-CIS) 기반 재현과 전체 코드 공개
2. 공격에 그치지 않고 방어까지 적용하여, 강건성 회복과 정확도 손실을 함께 정량화
3. 시간순 분할과 운영 임계값을 명시한 투명한 평가 절차

> Lunghi et al.(2023)이 향후 과제로 제시한 "공개 사기 탐지 데이터셋에서의 기존 공격 비교"를 수행하고, Lunghi et al.(2026)이 남긴 방어 과제로 한 걸음 나아간다.

## 3. 개념 정의

### 3.1 용어

| 용어 | 의미 | 본 연구에서의 위치 |
|---|---|---|
| 적대적 머신러닝 (Adversarial ML) | 분야 전체 | 배경 서술 시 사용 |
| 회피 공격 (Evasion Attack) | 학습 완료된 모델을 속이는 공격 | 수행하는 행위 |
| 적대적 강건성 (Adversarial Robustness) | 공격 하에서 유지되는 성능 | 측정 대상 — 논문 제목 |
| 적대적 학습 (Adversarial Training) | 공격 예제를 학습에 포함하는 방어 기법 | 적용할 방어 |

"적대적 학습"은 특정 방어 기법의 고유명사이므로, 분야 전체를 지칭할 때는 사용하지 않는다.

### 3.2 위협 분류에서의 위치

```
위협
├─ 정보 탈취형 (Inference)          해당 없음
└─ 무결성 훼손형 (Integrity)
   ├─ 오염 공격 (Poisoning)         해당 없음 — 학습 데이터 접근 불가
   └─ 회피 공격 (Evasion)           ◀ 본 연구
      ├─ White box                  비현실적 — 모델 내부 접근 불가
      ├─ Black box                  ◀ 본 연구의 가정
      └─ Gray box
```

공격자는 모델 내부를 알 수 없으며 승인·거절 결과만 관찰할 수 있다는 Black box 가정이 사기 탐지 환경에서 가장 현실적이다.

## 4. 실험 설계

### 4.1 파이프라인

```
[데이터]   IEEE-CIS Fraud Detection (590,540건, 사기율 3.5%)
             │
             ├─ feature 3분류 (조작 가능 / 조건부 가능 / 불가)
             └─ 시간순 분할 (TransactionDT 기준, 앞 80% 학습 / 뒤 20% 평가)
             │
[① 탐지]   XGBoost, Random Forest, MLP
             └─ 운영 임계값 τ 결정 (검증셋에서 F2 기준 탐색)
             │
             ▼  Recall · Precision · PR-AUC  →  공격 전 기준선
             │
[② 공격]   (a) 규칙 기반 회피 — 금액 하향, 거래 분할, 시간대 이동
            (b) Decision-Based — 정상 거래에서 출발해 경계를 따라 접근
             └─ 양쪽 모두 도메인 제약 강제, 임계값 τ 주입
             │
             ▼  회피 후 Recall · 변경 항목 수 · 질의 횟수
             │
[③ 전이성] A모델 공격으로 생성한 거래를 B모델에 투입
             │
             ▼  교차 모델 회피율  →  모델 종속성 판정
             │
[④ 방어]   적대적 학습 — ②에서 생성한 회피 거래를 사기 라벨로 추가 후 재학습
             │
             ▼  재공격 시 회복률 · 평상시 데이터 성능 손실
```

### 4.2 탐지 모델의 정당성 확보

> **"공격 대상 모델이 부실해서 뚫린 것 아닌가?"**

이 반론을 차단하지 못하면 결과 전체의 신뢰성이 무너진다. 다음 다섯 가지로 대응한다.

**① 표준 알고리즘 채택**
자체 설계 모델을 사용하지 않고 해당 분야에서 확립된 알고리즘만 사용한다. XGBoost와 Random Forest는 정형 금융 데이터의 표준이며, 선행 연구도 동일 계열을 공격 대상으로 삼았다. "우리가 만든 모델"이 아니라 "업계가 사용하는 모델"이어야 한다.

**② 공개 벤치마크 대비 성능 검증**
IEEE-CIS는 Kaggle 대회 데이터이므로 공개된 성능 기준선이 존재한다. 상위권 솔루션의 AUC를 참조하여 본 연구 모델이 합리적 범위에 있음을 보고한다. 이것이 부실 모델이 아님을 입증하는 가장 직접적인 근거다.

다만 조건이 다르다는 점을 함께 다뤄야 한다. 캐글 상위권은 대회 test set 기준으로 점수를 받았고 시간 구조를 이용한 기법을 썼다. 우리는 시간순 분할에 누수를 막고 가므로 숫자가 낮게 나올 수 있고, 그대로 비교하면 "모델이 부실하다"로 읽힌다.

**그래서 같은 데이터로 두 모델을 학습해 나란히 보고한다.** 하나는 무작위 분할에 누수를 막지 않은 모델이고, 다른 하나는 시간순 분할에 누수를 막은 모델이다. 앞의 숫자가 높게 나올 것이며, 그 차이가 곧 누수가 부풀린 양이다. 우리가 낮은 쪽을 알고 골랐다는 것을 보이는 것이 목적이고, 1.2절의 표를 실제 숫자로 채우는 일이기도 하다. 공격은 시간순 모델에만 수행한다.

**③ 다중 모델 동시 공격**
3종 모델을 각각 공격한다. 모두 회피된다면 특정 모델의 결함이 아니라 문제 자체의 성질이다. Carminati(2020)가 6종 탐지기를 공격해 회피율 범위를 제시한 것과 같은 논리다.

**④ 하이퍼파라미터 탐색 수행 및 명시**
기본값을 그대로 사용하지 않고 탐색을 거친 뒤, 탐색 범위와 최종 설정을 논문에 기재한다.

**⑤ 집계 feature 포함**
실제 사기 탐지 시스템의 핵심 방어 요소는 과거 이력 기반 집계 feature다. IEEE-CIS의 C·D 그룹과 V 그룹이 이에 해당하며, 이를 제외하지 않고 포함하여 학습한다. 방어에 유리한 요소를 의도적으로 배제하지 않았음을 보장한다.

포함이 실제로 방어에 기여하는지는 포함 여부를 바꾸어 확인한다. 전체 feature로 학습한 모델과 V 339개를 제외하고 학습한 모델을 같은 공격으로 치고 회피율을 비교하면, 익명 집계 feature의 방어 기여도가 수치로 나온다. 7장의 "어떤 요소가 방어에 기여하는지 분석"이 이 비교다. 작업량이 넘치면 9장에 따라 축소하되, 축소한 사실을 논문에 적는다.

### 4.3 구현상 반드시 처리할 사항

**임계값 주입**
공격 라이브러리의 기본값 0.5는 불균형 데이터에서 무효하다. 실제 운영 임계값 τ를 주입하지 않으면 공격이 성공한 것으로 오판하고 조기 종료된다. Cartella(2021)는 이 처리만으로 성공률이 0%에서 100%로 변화함을 보였다.

**수정 가능 항목 제한**
공격 라이브러리는 모든 항목을 바꾸려 든다. 3분류표를 보고 못 바꾸는 항목은 원래 값에 묶어둬야 한다.

**값 범위 보정**
금액의 양수 조건, 정수형 유지, 시각의 유효 범위 등을 강제한다. 생성된 모든 거래가 제약을 통과하는지 검증하는 함수를 별도로 작성한다.

### 4.4 코드 설계

데이터 로딩 계층을 분리하여, 이후 BAF·Elliptic 확장 시 나머지 파이프라인을 재사용할 수 있도록 작성한다.

## 6. 평가

### 6.1 지표

사기율 3.5%의 불균형 데이터이므로 정확도(accuracy)는 사용하지 않는다. 모든 거래를 정상으로 예측해도 96.5%가 나오기 때문이다.

| 지표 | 의미 | 역할 |
|---|---|---|
| Recall | 실제 사기 중 탐지 비율 | 주 지표 — 공격 전후 변화 |
| Precision | 사기 판정 중 실제 사기 비율 | 오탐 부담 |
| PR-AUC | 불균형 하 종합 성능 | 임계값 무관 비교 |
| 변경 항목 수 | 회피에 필요한 조작량 | 공격 비용 — 적을수록 심각 |
| 질의 횟수 | 모델 호출 횟수 | Black box 현실성 |

### 6.2 결과표 형식

| 조건 | Recall | Precision | PR-AUC | 변경 항목 수 |
|---|---|---|---|---|
| 공격 전 (기준선) | | | | — |
| 규칙 기반 공격 후 | | | | |
| Decision-Based 공격 후 | | | | |
| 방어 후 + 동일 공격 | | | | |
| 방어 후 + 평상시 데이터 | | | | — |

마지막 두 행이 강건성과 정확도의 상충 관계를 정량화한다. 방어의 이득과 대가를 함께 보고하는 것이 본 연구의 서술 원칙이다.

### 6.3 재현성 확보

- 시간순 분할 코드 공개
- 운영 임계값 결정 절차 명시
- 도메인 제약 정의 파일 공개
- 난수 시드 고정
- 실행 환경 파일 포함

**분할 경계에 여유 기간(embargo)을 두지 않는다.** 학습셋의 마지막 거래와 검증셋의 첫 거래가 7초 차이다. 사기는 신고가 들어와야 라벨이 붙으므로, 경계 직전 거래의 정답을 배포 시점에는 몰랐을 수 있다. 그래도 여유를 두지 않는 이유는 사기 탐지에서 그렇게 자르는 것이 표준이고, 여유 폭을 정할 근거가 없으면 자의적인 값이 되기 때문이다. **여유 기간이 없다는 사실을 논문에 명시한다.** 심사에서 먼저 지적당하는 것보다 먼저 밝히는 편이 낫다.

## 7. 예상 결과와 해석

연구는 결과를 모르는 상태에서 시작하므로, 결과별 해석을 사전에 정의한다.

| 결과 | 해석 | 논문에서의 서술 |
|---|---|---|
| 공격이 쉽게 성공 | 현행 탐지 모델이 적대적 조작에 취약 | 취약성 경고와 방어 필요성 |
| 공격이 어려움 | 집계 feature 등이 방어에 기여 | 어떤 요소가 방어에 기여하는지 분석 |
| 방어 후 크게 회복 | 표준 방어가 유효 | 실무 적용 근거 |
| 방어 후 회복 미미 | 정형 데이터 방어의 한계 | 후속 연구 필요성 |
| 전이성 높음 | 공격이 모델 비종속적 | 위협 심각도 상승 |
| 전이성 낮음 | 공격이 모델 특화적 | 모델 다양화가 방어책 |

어느 결과든 보고 가치가 있다. 이것이 개발과 연구의 결정적 차이다.

## 8. 예상 반론과 대응

**Q. 수치를 조금씩 바꾸어 넣는 것이 일반적인 테스트와 무엇이 다른가.**

탐색 방향이 다르다. 일반 테스트는 원 분포에서 무작위 추출하여 평균 성능을 측정하지만, 적대적 공격은 모델이 오분류하는 방향으로 의도적으로 탐색하여 최악 성능을 측정한다. 또한 무작위 변형은 잔액 초과나 음수 금액처럼 현실에 존재할 수 없는 거래를 생성하나, 본 연구는 도메인 제약을 강제하여 실제 실행 가능한 거래만 생성한다.

**Q. 결국 해당 데이터에만 유효한 결과가 아닌가.**

타당한 지적이다. 다만 공격 연구는 "취약성이 존재한다"는 존재 명제이므로 단일 반례로도 주장이 성립한다. "모든 공격을 막는다"는 전칭 명제인 방어와는 논리 구조가 다르다. 그럼에도 일반화를 위해 동일 데이터에서 3종 모델을 공격하고, 공격의 전이성을 측정하며, 후속 연구에서 BAF·Elliptic으로 확장한다.

**Q. 공격 대상 모델이 부실해서 뚫린 것이 아닌가.**

자체 설계 모델이 아닌 업계 표준 알고리즘을 사용하고, IEEE-CIS의 공개 Kaggle 벤치마크 대비 성능을 보고한다. 하이퍼파라미터 탐색 범위와 최종 설정을 명시하며, 실제 시스템의 핵심 방어 요소인 집계 feature를 제외하지 않고 포함한다. 또한 3종 모델을 모두 공격하여 결과가 특정 모델의 결함이 아님을 보인다. 상세는 4.2절 참조.

**Q. 공격만 제시하는 것은 논문의 방향이 아니다.**

수용하여 적대적 학습 기반 방어를 본 연구에 포함한다. 방어 적용 후 강건성 회복과 평상시 성능 손실을 함께 측정하여 공격과 방어의 완결된 구조로 구성한다.
