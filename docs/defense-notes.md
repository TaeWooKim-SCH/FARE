# 방어(적대적 학습) 구현 노트

파이프라인 ④ 방어를 구현할 때 다시 볼 것. 적대적 학습에서 두 가지가 반드시 문제가 되는데, 둘 다 research-plan.md 7장이 예상한 "방어 후 회복 미미 → 정형 데이터 방어의 한계"로 이어지는 측정 대상이다. **버그가 아니라 재야 할 현상이다.**

## 리스크 1 — 공격 특화 과적합

규칙 기반 공격으로 만든 회피 예제로만 학습하면, 모델이 딱 그 공격 패턴만 방어하고 조금 다른 공격엔 다시 뚫린다. 적대적 학습에서 잘 알려진 함정이다.

- 고전적 과적합(train 좋고 test 나쁨)은 시간순 분할 평가 + 원본에 섞어 재학습으로 막는다.
- 트리 모델(XGBoost/RF)의 "적대적 학습"은 사실상 적대적 예제를 데이터 증강으로 넣는 것이라 gradient 기반 반복 AT보다 덜 폭주한다. 그래도 아래 오탐 맞바꿈은 똑같이 생긴다.

## 리스크 2 — 정상 거래까지 차단(오탐 폭주)

회피 예제는 정상 소액·평시 거래와 특징 공간에서 겹친다(공격이 회피하는 방식이 곧 정상을 흉내 내는 것이므로). 이걸 사기로 학습하면 비슷하게 생긴 진짜 정상 거래도 사기로 찍어 오탐이 폭증한다. 금액·시각만으로 사기와 정상이 안 갈리는 만큼을, 방어는 오탐(정상 차단)으로 지불한다.

- 무한 폭주는 안 한다: 모델은 점수를 내고 τ로 자르므로, 방어 후 τ를 검증셋에서 다시 잡으면 목표 오탐율에 맞춰 재조정된다. 대가는 "같은 오탐율에서 recall이 얼마나 빠지나"로 나타난다 = 정밀도-재현율 맞바꿈.
- 계획서 방어는 1라운드(공격 예제 추가 → 재학습 → 재측정)다. 반복 AT는 돌수록 경계가 정상 영역으로 파고들어 오탐이 커지므로, 반복할 거면 라운드마다 평상시 성능을 찍는다.

## 만들면 안 되는 검사

정합성 검사를 방어에 쓰려는 유혹이 생기는데, 아래 둘은 정상 거래에서 이미 깨져 있어 오탐만 낸다.

- **`V >= TransactionAmt` 부등식** — 원본 금액에서 이미 20.08%(사기 행 29.44%)가 위반이다. 오탐 20%짜리 검사다.
- **같은 엔티티 안에서 C가 역행하면 조작으로 보는 검사** — 손대지 않은 정상 거래에서 이미 C13이 12.30%, C14가 9.66%, C1이 9.68% 역행한다.

## 구현 가드레일

1. 적대적 예제만으로 학습하지 말고 원본에 섞는다.
2. 방어 후 τ를 검증셋에서 재조정하고, 고정 오탐율 기준으로 공격 전후를 비교한다.
3. A 공격(규칙 기반)으로 학습 → B 공격(Decision-Based)으로 평가해 공격 특화 과적합을 탐지한다.
4. 매 측정에 "평상시 데이터" Recall·PR-AUC를 같이 보고한다(방어의 대가).
5. recall만 보지 말고 Precision·PR-AUC로 오탐을 감시한다.
6. 반복 AT면 라운드별로 기록한다.
